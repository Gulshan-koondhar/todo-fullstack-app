Project: Phase IV – Local Kubernetes Deployment

Core principles:
- Strict spec-driven deployment only using Claude Code and Spec-Kit Plus
- Stateless architecture with all persistent state stored externally (Neon PostgreSQL)
- Reusability of infrastructure intelligence through Helm subcharts and deployment blueprints
- Security-first: sensitive values (API keys, DB credentials, JWT secrets) managed exclusively via Kubernetes Secrets
- Cloud-native readiness: horizontal scalability, resilience to pod restarts, observability via AIOps tools
- AIOps-assisted operations: leverage kubectl-ai and kagent for manifest generation, troubleshooting, and scaling

Key standards:
- All Kubernetes manifests, Dockerfiles, and Helm templates must be generated by Claude Code from refined specs
- No manual editing of YAML, Dockerfiles, or Helm files — only spec iteration allowed
- Secrets and environment variables must never be hardcoded in code or manifests
- Every deployment component (frontend, backend, MCP server) must be containerized with proper multi-stage Dockerfiles
- Helm charts must be structured for reusability (values overrides, subcharts if applicable)
- AIOps usage must be documented in specs (prompts used with kubectl-ai/kagent)
- Monorepo organization: /docker, /helm, /k8s/raw (optional), /specs/deployment-phase-iv
- All changes must preserve Phase III functionality (stateless chat endpoint, AI agent + MCP tools)

Constraints:
- Local cluster only: Minikube (no cloud K8s in this phase)
- Container runtime: Docker images built locally and loaded into Minikube
- Exposure: Minikube service, tunnel, or Ingress (no external cloud load balancers)
- No new backend features or AI logic changes — only deployment & orchestration

Success criteria:
- Full application (login, task CRUD, AI chatbot) runs reliably inside Minikube
- Stateless behavior validated: pod restarts do not lose conversation state (persisted in Neon DB)
- Secrets properly injected and used (DB connection, OpenAI key, JWT)
- Basic scaling demonstrated (multiple replicas of backend)
- AIOps tools used to generate or debug at least one resource
